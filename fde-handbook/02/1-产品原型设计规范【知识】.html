• [ ] 需求清单每条五字段齐全（ID/描述/优先级/验收标准/约束），缺"验收标准"或"约束"的先补

• [ ] 每条痛点能追溯到具体用户和场景（用用户原话，不是自己解读）

• [ ] 目标场景的验收标准可量化（带数值或百分比，如"≤30秒""准确率≥95%"）

• [ ] 业务流程每个节点的输入输出清楚，数据流转链路清楚

⚠️ 红线：缺"验收标准"或"约束条件"的需求，先退回补齐。这两项是智能体生成原型和测试用例的根基，缺了就是让它在真空中设计。

1.3 为什么统一用这个智能体

• 标准：提示词、组件库、栅格、视觉风格都锁在智能体里，谁调都是一个样，不飘

• 快：方法都内置在智能体里，约 3 小时出一版可交互原型

• 可复制：换行业时，智能体+技能这套不变，只换喂进去的需求确认表

• 好协作：产出走纳米 Work 项目共享目录，团队直接拿

那些结构化拆解、六区块 Prompt、稳定性四板斧的具体方法，是智能体内部封装好的——操作岗不用背、不用手拼。想知道它内部怎么干活的，看附录。

二、原型设计的质量要求（人要把关的，智能体代不了）

智能体能出正常路径的原型，但"出错了怎么办"和"流程通不通"得人判断。这两关卡死，原型才算过关。

2.1 边界条件五类（智能体容易漏，逐页对）

AI 最擅长画"正常路径"，最不擅长想异常。每页原型都要覆盖五类边界：

类别

检查项

原型要画的状态

输入边界

空输入/超长/特殊字符/非法格式/超大文件

提示态、截断态、报错态

输出边界

空结果/超大结果集/导出限制/分页

空状态图、分页器、限额提示

权限边界

无权限/权限不足/越权/多角色冲突

403页、灰化按钮、提示文案

并发边界

重复提交/并发编辑/锁冲突

禁用态、冲突提示、乐观锁

异常边界

网络中断/服务超时/依赖不可用

重试按钮、降级提示、错误码

附 1　需求结构化拆解（四要素法）

每条口语化需求，先拆成四个要素，翻译成能精确执行的结构化指令：

结构化 Prompt 模板：

```

【角色】{主体}，权限级别：{权限}

【场景】{主体}在{什么场景下}需要{做什么}

【动作】{动词}{对象}，目标：{达成什么业务结果}

【输入】操作所需的数据/文件：{具体说明}

【输出】操作后产生的结果：{具体说明}

【约束】{前置条件 + 限制 + 异常处理要求}

【关联】与哪些需求/页面有依赖：{列出 REQ-ID}

【优先级】P{0/1/2}

```

附 4　六区块 Prompt 模板

原型稳定生成的核心，缺一区块输出就漂移：

```

【区块1·页面定位】页面名称/所属模块/页面类型/优先级

【区块2·角色与入口】使用角色+权限/入口路径/退出路径

【区块3·功能区清单】本页功能区(≤5个)，按主次排序

【区块4·布局规范】布局类型/12栏栅格/组件库/视觉风格

【区块5·交互规则】操作→反馈→跳转；异常→提示方式

【区块6·边界条件】空数据/加载中/权限不足/超长/并发 各状态

```
