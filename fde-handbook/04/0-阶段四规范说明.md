# 阶段四 · 纳米Work 行业工作台——规范说明

> 这个阶段干什么：把阶段二的产品原型、阶段三的智能体矩阵，变成客户能访问、能用的行业工作台。这是五阶段里最容易失控的一步——每个人搭法不同、代码风格乱，没标准就没法复制。文档分两类：带【知识】的是要学会、照着做的规范和方法；本阶段的【交付】不是文档，是能跑的系统本身（见第三节）。

## 二、标准动作流程（五步走）

① 建模 → ② 后端开发 → ③ 前端开发 → ④ 联调 → ⑤ 上线

**第一步：建模（照 api-er-modeling）**
用 api-er-modeling skill 从功能清单推导实体、理清表关系、画 ER 图。拿真实数据演练业务逻辑：一条数据从创建到流转能不能跑通、哪张表缺字段、哪个关联断了。建模不通，后面全白搭。设计好的表结构交给 api-model-generator 落成 ORM 代码。

**第二步：后端开发（照 api-guide）**
用 api-* skill 生成路由/服务/模型/迁移。分层架构必须遵守：api（路由）→ services（业务）→ managers（编排）→ db（数据），依赖方向不能反。业务查询强制带 `hospital_id` 多租户过滤。

**第三步：前端开发（照 vben-guide）**
用 vben-* skill 生成页面/表格/表单/看板。技术栈锁死 Vue 3 + TypeScript + Vben Admin 5 + Element Plus（`@vben/web-ele`），不自由发挥。

**第四步：联调**
前端调后端走 `requestClient`（@vben/request）封装，跑通真实数据——数据真能从库里查出来、显示到页面上，不是 mock。

**第五步：上线**
走极库云流水线 → 360 智汇云容器云，提供可访问 URL，鉴权走通（客户登录进得去），真实数据能显示、能操作。先还原 demo 拿去演示，再补齐完整功能到能上线，别一口气憋大的。

**本阶段节奏与卡点**：这是 **3/7/14 交付版本的主场**。前提是**两线齐备**——阶段三需求签字定稿 + 环境线底座就绪（网络 / VPN / 基础服务都通了），**从这儿起算**，按需求大小交付一版：小需求 3 天、中等 7 天、较大 14 天。不追求一次做完，每版交一个能验证的东西、拿反馈滚下一版；需求大就多轮迭代，即（2+1）× n。**加时卡点**：接口 / 数据 / 上线环境不到位——等甲方给接口给资料、开上线权限的时间算「加时周期」，单独记。细则见 [[FDE项目推进节奏机制]]。

## 四、几条铁律

1. 技术栈锁死、目录统一、用现成 skill，不自由发挥——技术栈一乱，复制就无从谈起
2. 上游给垃圾，下游出精致的垃圾——功能清单缺"关联智能体"或"数据依赖"的，实现岗有权打回
3. 建模不通不许往下走——ER 模型是后面所有功能的根基
4. 跑真实数据，不是 mock——数据真能查出来、显示出来才算数
5. 先 demo 后完整——先还原核心流程演示，验证方向对了再补齐

## 五、做到什么算过关

- 技术栈合规——用的是统一技术栈（FastAPI + Vben/Element Plus），没自由发挥
- 能访问——有可访问 URL，客户点进去打得开
- 鉴权通——登录/权限走得通，多租户 `hospital_id` 隔离有效
- 数据通——真实数据能查、能显示、能操作，不是 mock
- 代码规范——过 ruff（后端）、过 lint（前端），过 redline-guard 门禁，目录结构统一
- demo 先行——先出 demo 演示过，再补完整功能
- 部署文档——有部署说明，别人能照着重新部署

全打勾，才算工作台搭扎实，可以交棒阶段五做客户试用。
