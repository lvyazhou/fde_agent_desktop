# 项目进度表【交付】

> 阶段四「纳米Work行业工作台」的交付物。本质是**项目甘特图**——把工作台开发从启动到上线的全过程,按任务条排在时间轴上,管起止日期、里程碑、依赖和风险。相当于这个阶段的项目管理主表。

## 这是什么

阶段三的《项目任务计划表》定了要做什么、谁做;到了阶段四实际开发,用这张甘特图把每项任务落到**具体的起止日期**上,排出整体工期,标出关键里程碑,盯着计划 vs 实际的偏差走。

一句话:从项目哪天开始、哪天结束,中间每段谁在做、做到哪、卡在哪,全在这一张图上。

## 甘特图结构(横轴=时间,纵轴=任务)

```
任务项            负责人   ─────────── 时间轴（周/天）───────────
需求/功能清单确认  PM       ██
ER 建模           建模      ▓▓▓▓
后端开发          后端            ▓▓▓▓▓▓▓▓
前端开发          前端              ▓▓▓▓▓▓▓▓
智能体接入         全栈                    ▓▓▓▓
联调测试          全员                          ▓▓▓▓
部署上线          运维                              ██◆里程碑
```

## 表字段(照填)

| 字段 | 说明 |
|---|---|
| 任务项 | 对应任务计划表里的条目 |
| 负责人 | 建模/后端/前端/联调各段责任人 |
| **计划开始 / 计划结束** | 甘特条的起止(排工期用) |
| **实际开始 / 实际结束** | 实际推进,和计划对照看偏差 |
| 状态 | 未开始 / 进行中 / 已完成 / 阻塞 |
| 完成度 | 百分比 |
| 依赖项 | 卡在谁手上、等前置任务完成 |
| 里程碑 | demo 就绪 / 完整功能就绪 / 上线等关键节点 |
| 风险/备注 | 延期原因、需要拉齐的事 |

## 关键里程碑(建议固定的节点)

- **M1 建模完成**:ER 模型走过真实数据,进开发的前置门
- **M2 demo 就绪**:P0 功能跑通,验方向
- **M3 完整功能就绪**:P0+P1+异常+权限补齐
- **M4 部署上线**:能访问,交付阶段五

## 盯什么

- 建模 → 后端 → 前端 → 智能体接入 → 联调 → 部署,六段是否按序推进、有没有并行冲突
- 关键路径上的任务有没有延期(延一天整个工期跟着延)
- 阻塞项 48h 内是否升级处理

## 产出去向

工作台上线(M4)= 阶段五客户试用的输入。进度表在阶段四内部用于项目管理,不需客户签字。
