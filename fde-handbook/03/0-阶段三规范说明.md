# 阶段三 · 需求确认-智能体设计——规范说明

> 这个阶段干什么：阶段二拿对接确认表做了原型、把需求收敛对齐了；阶段三**第一件事是把收敛后的需求签字定死**（需求最终确认表 + 任务计划表 + 验收标准表），再把一条业务链路拆成**智能体矩阵**——一个环节一个专用智能体，各管一段首尾相接，过 Eval 门禁才上线。
>
> **一条铁律**：以智能体设计为主，平台为辅。
>
> **一句话主线**：需求签字定稿 → 拆智能体矩阵 → 逐个照设计表填 → 配六组件 → A/B调优 → 过Eval门禁上线。

---

## 一、文档清单与用法

> 这个阶段有 **4 件【交付】**（1 号设计表 + 2/3/4 号三张需求签字表）和 **6 份【知识】**（5-10 号配套方法模板）。先签字定稿需求，再照设计表逐个做智能体，用知识模板配好六组件，过测试评测。

| # | 文档 | 类型 | 怎么用 |
|---|---|---|---|
| 1 | 智能体设计表 | 📝【交付】 | 每个智能体填一份——身份卡→五层拆解→六组件→提示词→知识库→技能→A/B→验收上线，一份自包含 |
| 2 | 需求最终确认表 | 📝【交付】 | 需求收敛定稿、客户签字——项目概述/痛点/AI赋能方案/需求清单/场景/验收/四方签字 |
| 3 | 项目任务计划表 | 📝【交付】 | 需求签字后填——五阶段排期、里程碑、交付时间，客户签字定死 |
| 4 | 项目验收标准表 | 📝【交付】 | 每条需求的验收口径、实测值、三态判定（也作需求确认表附章） |
| 5 | 知识库配置标准模板 | 📖【知识】 | 配知识库——按类型切片灌行业知识，让智能体懂行 |
| 6 | 提示词工程标准模板 | 📖【知识】 | 写提示词——六要素结构，含招投标完整示例、版本管理 |
| 7 | 技能Skill标准模板 | 📖【知识】 | 挂技能——单一职责、输入输出规范、代码/单测/文档示例 |
| 8 | 连接器标准模板 | 📖【知识】 | 接数据——把业务数据接进智能体，含 MCP 说明 |
| 9 | AB测试标准模板 | 📖【知识】 | 调效果——对比不同方案，挑最优 |
| 10 | Eval评测标准模板 | 📖【知识】 | 过门禁——上线前质量评测，准确率达标才放行 |

## 二、标准动作流程

```
阶段二交棒（对接确认表 + AI能力清单 + 原型认可）
│
① 需求签字定稿 → 填【交付】2/3/4
（对接确认表收敛后的需求签字定死；同步定任务计划表、验收标准表）
│
② 拆矩阵 → 一个环节一个智能体，画出智能体矩阵
│
③ 逐个设计 → 每个智能体照【1号 设计表】填：身份卡→五层拆解→六组件
│
④ 配六组件 → 用【5号 知识库】【6号 提示词】【7号 技能】【8号 连接器】分别配
│
⑤ 测试调优 → 用【9号 A/B测试】挑最优提示词/编排
│
⑥ 过评测门禁 → 用【10号 Eval】，准确率达标才上线
│
▼ 智能体矩阵端到端能跑、准确率达标 → 交棒阶段四做工作台
```

## 三、需求签字定稿（进智能体设计前先干这一步）

> 阶段二拿对接确认表做了原型、用原型把需求收敛对齐了；阶段三第一件事，就是把收敛后的需求**签字定死**，同步把任务计划、验收标准跟客户定下来。这是后面所有智能体设计的唯一依据——**需求没签、没定死，别急着设计智能体，猜错一条后面全返工。**

交出三张【交付】表：
- 《2-需求最终确认表》——需求收敛定稿、客户签字
- 《3-项目任务计划表》——需求签字后排期、定交付时间
- 《4-项目验收标准表》——逐条量化验收口径、客户签字

**本阶段节奏与卡点**：这一步是 **2+1 的“1”落定**——阶段二跑完 2 次对接、出了原型，到这儿把需求签字定死。**签字是外部项目最大的加时卡点**：甲方内部流程没走完、拍板人没点头，字就签不了，原型定不了稿、后面全卡住——**这时第一动作是发邮件告知甲方**（写清卡在哪、在等什么），白纸黑字留痕、防后面时间扯皮；等甲方走流程、拍板的时间算「加时周期」，暂停计时、单独记。签字一落，跟环境线的“底座就绪”合流，进阶段四按 3/7/14 交付版本。细则见 [[FDE项目推进节奏机制]]。

## 四、智能体矩阵设计（本阶段核心方法）

四条设计原则：单一路径 / 输入输出闭环 / 边界清晰 / 可独立评测。一个环节一个智能体，上游输出=下游输入，数据流首尾闭环。手册示例链路：售前全流程（线索→策略→方案→POC→招投标）。

---

## 五、七条铁律

1. 需求先签字再设计智能体——需求最终确认表没签，不进智能体设计
2. 一个环节一个智能体——不越界、不重叠，数据流首尾闭环
3. 边界和异常最容易漏——正常路径谁都会写，异常兜底和转人工规则才是上线不翻车的关键
4. 提示词从五层拆解来——规则从 Playbook 提取、输入输出从节点表提取，不拍脑袋写
5. 优先用平台标准 Skill——**64 个标准 skill**（api-* 32 + vben-* 32）能复用就别自研
6. 准确率达标才上线——过 Eval 门禁，准确率 ≥90% 不达标不放行

---

## 六、做到什么算过关

- [ ] 需求最终确认表 + 任务计划表 + 验收标准表三张签完，需求定死
- [ ] 智能体矩阵画好——每个智能体只管一个环节，无重合无遗漏
- [ ] 数据流闭环——上游输出 = 下游输入，无断点
- [ ] 每个智能体照 1 号设计表填全，五层拆解含边界+异常
- [ ] 六组件配好——提示词/知识库/技能/连接器各按对应模板
- [ ] A/B 测试挑出最优方案
- [ ] 过 Eval 评测门禁，准确率达标

> 全打勾，才算智能体设计做扎实，可以交棒阶段四做工作台。
