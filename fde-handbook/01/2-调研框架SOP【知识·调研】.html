谁用：FDE 项目经理进客户门前，手里揣着这份框架去聊。
干什么用：保证每次调研都把该问的问全、该记的记全，不靠临场发挥、不漏项。
配套：怎么问看《调研话术卡》，问什么、记什么、确认什么看这份 SOP。

一、每次调研必须聊出来的六项

带着这六项去聊，一项都不能空着回来。

#

要聊出来的

具体挖什么

聊到什么算够

1

目标

客户做这件事想达到什么、成功长什么样

能说出一句可衡量的目标

2

客户要什么

客户嘴里的诉求、期望的功能

列出具体想要的东西

3

痛点

现在最烦、最耗时、最容易出错的是什么

每个痛点能追溯到具体场景和人

4

价值

做成了能省多少时间/钱、解决多大问题

痛点能量化（原来几天→几分钟这种）

5

业务流程

这件事从头到尾怎么走，每个节点的输入、输出

能画出一条完整流程线，每个节点知道进什么、出什么

6

数据流程

数据从哪来、经过哪些处理、到哪去

能画出数据流转链路，知道每段数据从哪个系统取

重点是第 5、6 项——业务流程要拆到每个节点的输入输出，数据流程要理清从源到用的完整链路。这两项是后面 ER 建模和智能体设计的根基，聊不清楚后面全是猜。

二、边聊边记（怎么留证）

聊的同时把过程记下来，别指望回去凭记忆补。

记录方式

用来记什么

提醒

纳米 AI 录音

整场对话，事后可回放、可转文字

开录前跟客户打声招呼，让客户知道在录

录屏

客户演示系统操作、现有流程

录客户屏幕/系统前，先跟客户确认一下

截图

客户现有报表、界面、数据样例

截敏感数据前问一句客户方不方便

客户提供的资料

组织架构、系统清单、数据字典、制度文件

让客户明确哪些能给、哪些涉密

一句话：录音、录屏、截图、要资料——都是好东西，但动手前跟客户确认一声。既是合规，也是让客户知情、建立信任。别偷偷录。

三、技术侧要确认的两件事

业务聊清楚了，技术可行性也得当场对齐，别等做的时候才发现坑。

要确认的

为什么现在就要确认

外部 API 收费问题

如果方案要调第三方 API（地图、短信、行业数据等），谁付费、多少钱、走谁的账号——不确认，上线时卡在钱上

基础技术方案确认

部署在哪（公有云/私有化/信创）、网络怎么通、跟客户系统怎么对接——大方向客户认了，才好往下做

四、聊完出门前自检

对着这张单子过一遍，缺哪项当场补，别带着窟窿回去：

• [ ] 六项都聊到了（目标/要什么/痛点/价值/业务流程/数据流程）

• [ ] 业务流程每个节点的输入输出都清楚

• [ ] 数据流程从源到用的链路都清楚

• [ ] 录音/录屏/截图/资料都留了，且客户知情

• [ ] 外部 API 收费问题问清楚了

• [ ] 基础技术方案跟客户对齐了

一句话

带着六项框架去聊、边聊边留证（客户知情）、技术可行性当场对齐——一次调研把该挖的挖全、该记的记全、该确认的确认掉，回去才不用猜。
