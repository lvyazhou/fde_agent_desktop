00

你来是干嘛的

🕐 3 分钟
开场怎么说"开始前先把你们的角色一句话说清——FDE 不签单、不谈价,就管三件事。这三件事记住了,后面所有内容都是围着它转的。"
  • 三件事:需求对接、技术信任、方案落地。带 3–5 人小组,把客户一句话做成线上能用的工作台。
  • 不越界:价格转商务、竞品不主动谈、不替客户拍业务的板。
  • 一条总铁律:以智能体设计为主、平台为辅。别一上来折腾平台。
  • "验收 vs 真有人用"的区别——一句话点一下,细节留到模块 07 讲使用率时展开。
提问钩子"谁能用一句话说清 FDE 和销售的区别?"——等一个人答,顺势收口到"对,我们管落地不管签单"。
转场角色清楚了。→"那这活到底怎么一步步干下来?先看整根骨架——五阶段。"
01

FDE 五阶段总览

🕐 10 分钟 · 重头
开场怎么说"这块是骨架课,后面全挂在这。你只要记住一条链 + 三套节奏 + 三处签字,这块就过了。"
  • 一条链:客户一句话 → 调研备弹 → 沟通出原型 → 需求确认+智能体设计 → 工作台上线 → 试用定稿 → 复制下个行业。用盖楼的比喻带一遍。
  • 两条线并行:需求主线(对业务科室)+ 环境地基线(对信息科开 VPN/部署)。两线各走各的,两线齐了才交付版本。
  • 三套节奏别混:2+1(数"次",需求侧)· 3/7/14(算"天",签字后开发)· Sprint S1–S4(团队推进骨架)。
  • 三处签字:S1末对接确认表 · S2初需求最终确认表 · S4末交付签字表。漏一处后面返工。
  • Sprint 四段各几天、数据治理最易超时——有时间展开,紧了就指图让自读。
  • 加时赛规则(甲方卡住发邮件留痕)——一句话带过。
👉 图
五阶段与Sprint关系图:"上面一条是客户看到的五阶段,下面一条是你们团队的两周节奏,一一对应。你就记下面三个红框——三处签字卡口,一处都不能省。"
提问钩子报三个场景(改需求跑第三轮 / 签字后开发 / 甲方不开 VPN),问各属哪套节奏。全场抢答,热身效果好。
转场骨架有了。→"但走进医院,数据都在哪些系统里?这是新人最容易懵的一块,先补医疗底。"
02

医疗行业架构

🕐 7 分钟
开场怎么说"医疗智能体的燃料是数据,数据都躺在几个系统里。这块记住一个源头、一个'多半没有',就够上手了。"
  • 五大系统:HIS(挂号收费,所有业务数据源头)· EMR 病历 · LIS 检验 · PACS 影像 · CDR 汇总仓库。
  • 关键认知:CDR 要过较高互联互通等级才建得起来,大多数医院没有——这就是要做 SDR 的原因(埋钩子,下一块揭)。
  • 一条现场铁律:只跟 IT 聊不出业务需求,决策权在业务科室,信息科是给数据的配合方。
  • 智能体矩阵(围术期/质控/患者/运营/HR)——报一遍名字,说"接新场景先看能不能搬"。
  • 术语表(国考/DRG/CMI/药占比/耗占比/平均住院日/互联互通)——别逐条念,说"这张表课后背,客户随口说术语你能接住就算过"。
👉 图
五大系统数据流图:"顺着箭头看——HIS 是源头,往下汇。重点是这条灰色虚线:多数医院没 CDR,SDR 就直接接各系统。记住智能体永远走最右边的 SDR。"
提问钩子"客户说'从 HIS 拉个数据',你第一反应问什么?"——引出"数据在哪张表、跟别的系统通不通",带出草图意识。
转场系统认识了。→"那我们拿什么把这些数据接起来、喂给智能体?这就是藏在背后的两块地基——SEAF 和 SDR。"
03

技术底座 · SEAF + SDR

🕐 8 分钟
开场怎么说"这块讲两个藏在背后的地基。记住三句话:对客户只有一个纳米Work、SDR 是取数唯一入口、去医院必被问数据安全。"
  • SEAF 用发电厂比喻:对外只有一个产品——纳米Work 工作台;SEAF 像发电厂,藏底层供能不露面。客户只碰插座和电器。
  • SDR 是地基不是锦上添花:商业化项目全卡在"数据太多太乱拿不出来"。没数据 → 智能体是空壳。
  • SDR vs CDR 一句话:智能体从不直连医院数据库,一律走 SDR。有 CDR 就抽 CDR,没 CDR 就直接接各系统。
  • 数据安全三问答(去医院必被问):数据不出院(360私有云专属实例)· 离线模型不存储不联网不训练 · 180天可配审计。这三句背下来。
  • SDR 四个卡点对应四个解法——有时间过表,紧了指教程。
  • 平台实操自查清单(搭Agent/接Connector/Trace排错)——说"这五项在集训和跟岗手上练,今天只让你知道有这关"。
👉 图
SDR/CDR 区别对照图:"左边有 CDR 的医院轻松,右边多数医院没 CDR、SDR 累点。但你只要记最底下那句——智能体永远走 SDR,从不直连数据库。"
提问钩子"你是信息科主任,最担心什么?"——引出数据安全,顺势演一遍三问答,让学员感受现场压力。
转场地基有了。→"数据能拿到了,怎么把业务专家脑子里的经验,拆成一个个能跑的智能体?进最核心的技术阶段。"
04

需求与智能体设计

🕐 10 分钟 · 重头
开场怎么说"这是最核心的技术阶段,盖了阶段一二三。记住两把工具:挖需求的六项框架、拆智能体的五层拆解法。最后卡一道 Eval 门禁。"
  • 挖需求两件套:六项调研框架(目标/要什么/痛点/价值/业务流程/数据流程)+ 先问后讲、让客户自己说。
  • 先签字再设计:需求收敛成《需求最终确认表》签字定死——猜错一条后面全返工。
  • 五层拆解法:Workflow → 节点数据流 → Playbook → 边界 → 异常,映射到 Agent 六组件。边界和异常最容易漏。
  • Eval 门禁:准确率 ≥90% 才放行,不达标不上线。这是硬线。
  • 心内科"四步归因"样板(3天→15分钟)——有时间一定讲,这是最抓人的落地例子;真紧了才砍。
  • 七种咨询方法逐条(STAR/5W1H/量化锚定/四把钥匙)——说"显性靠前三种、隐性靠四把钥匙,吐槽法最好使",逐条留自读。
👉 图
五层拆解到上线流程图:"三层往下看——五层拆解(红色'异常'最爱漏)映射进六组件,调完过 Eval ≥90% 才放行。你手指停在红色异常框上强调一下。"
提问钩子给一个假场景("科室想看月度运营"),现场让两三个人各说一层拆解,你补边界和异常——立刻看出谁真懂。
转场智能体设计好了。→"设计是图纸,怎么真盖成能访问的系统?进阶段四——最容易失控的一步。"
05

行业工作台

🕐 6 分钟
开场怎么说"阶段四把前面的原型和智能体挂上去跑起来。记住:五步走 + 技术栈锁死。阶段四不重新设计,只把设计好的挂上去。"
  • 五步走:建模 → 后端 → 前端 → 联调(真实数据非mock)→ 上线(极库云→容器云给URL)。上一步输出=下一步输入。
  • 技术栈锁死:后端 FastAPI、前端 Vue3+Vben,多租户强制 hospital_id。技术栈一乱,复制无从谈起。
  • 一条铁律:建模不通不许往下走;先 demo 后完整,别一口气憋大的。
  • 三层门禁(铁律CLAUDE.md + 规范库 + CI硬拦截)约束 AI 别乱写——有时间提一句。
  • 64 个标准 skill 的细节——一句"照规范生成不从零手写",留自读。
👉 图
工作台五步走:"就一条流水线,建模在最左边——记住'建模不通不许往下走',这是最常翻车的地方。"
转场系统能跑了、要上线。→"上线走哪条路、怎么保证 A 院看不到 B 院数据?下一块极库云。"
06

极库云 + 容器云

🕐 4 分钟
开场怎么说"上线走一条固定链路,守两条硬要求。这块短,记链路 + 隔离就行。"
  • 上线链路:写代码 → 极库云(托管+CI)→ 360智汇云容器云(部署)→ 给客户可访问 URL。
  • 两条硬要求:多租户 hospital_id 隔离(数据串了是事故)· 无硬编码密钥。
  • 极库云三重身份(代码托管/知识库中心/CI)——有时间点一下。
  • 统一工具链五件套——一句"工具统一才能复制",留自读。
👉 图
上线链路图:"从左到右一条线到 URL 交给客户。红字那行(隔离+无密钥)是全程守住的底线。"
转场东西上线了。→"上线不是结束,是试运行的开始——怎么盯到真有人用?"
07

客户试用与优化

🕐 4 分钟
开场怎么说"产品做出来不算完,试运行才开始。记住三轮定稿 + 一条收官铁律。"
  • 三轮递进定稿:第一轮看方向 → 第二轮抠细节 → 第三轮定死。问题从粗到细,标准从松到严。
  • 收官铁律:验收只代表"当时能跑",30 天使用率才代表真有人用。30/60/90 天盯不同的事。
  • 反馈三分类(功能缺失/逻辑不通/体验)+ 五步处理——有时间提。
  • Trace 全链路回放——一句"出问题能定位是理解错还是工具错",留自读。
👉 图
三轮定稿漏斗图:"像漏斗,一轮比一轮窄、一轮比一轮严。别停在第一轮看着对就交付。"
转场交付闭环讲完了。→"这一路上有哪些规矩得守、日常在哪管项目?收口到项管规范。"
08

项目管理规范

🕐 5 分钟
开场怎么说"这块是贯穿全程的规矩,日常都落在极库云上。记住五类规范卡在哪、两类角色各干啥。"
  • 五类规范按时间线卡节点:签字前交付规范 → 设计时设计规范 → 开发中质量规范 → 要交付验收规范 → 交付后复制规范。
  • 两类角色:项目经理(大脑,指挥/盯进度/拍板,不下场)· 交付工程师(手脚,拆场景/搭系统/上线)。项目经理指挥、交付干活。
  • 三个闸口:72h 签字制 · 三个人工确认节点(原型签字/建模评审/合并审核)· P0–P3 响应 SLA。
  • 需求拆条→排版本→盯进度(10个需求拆10条排P0/P1/P2)——有时间用例子过一遍。
  • 产品复制模式(标品/定制化决策)——一句"标品照SOP快走,定制先评估",留自读。
👉 图
需求管理流程图:"用户10个需求 → 极库云拆10条 → 排进P0/P1/P2三个版本 → 交付每天更新。你只强调'别一锅端,按优先级装版本'。"
转场规矩清楚了。→"最后,把前面全部串一遍——实战演练怎么考出师。"
09

项目实战演练

🕐 3 分钟 · 收口
开场怎么说"前面八块学完,最后用实战串一遍。3–4 人一组接一个陌生医疗场景,从阶段一走到出 demo,答辩过五维评分。"
  • 五维计分卡:交付效率20% · 验收通过率25% · 30天使用率25% · 产品化贡献15% · 知识沉淀15%。后两项占30%,交付完得给体系留东西。
  • 质量三道防线:准入(无证不上岗)· 过程(S1–S4节点检查,卡住不许往下)· 结果(30/60/90天使用率)。
  • 场景剧本(教练智能体扮科室主任/信息科/临床医生)——有时间说玩法。
  • 分组任务每阶段产出物表——指教程,一句"每阶段都有明确产出物,不产出等于没学"。
收尾一句"记住今天最该带走的:以智能体设计为主、平台为辅;需求先签字再设计;验收只代表当时能跑,30 天使用率才代表真有人用。散会。"
留白提问"今天哪一块你觉得回去马上能用上?"——收集反馈,也让大家自己复述一遍重点。

  • 过半看表。讲到模块 05 该到 34 分钟左右;超了就把 06/07/08 的黄灯全砍成灰灯,主干照样完整。
