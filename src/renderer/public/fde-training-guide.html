00
开篇 · 先讲清你的角色

你来是干嘛的

学完能: 一句话说清 FDE 做什么、不做什么,分清"验收"和"真有人用"的区别。

讲白了,FDE(前线交付工程师)不签单、不谈价,就管三件事:需求对接、技术信任、方案落地。从进客户门那一刻起,你带一个 3–5 人小组,把一个医疗智能体产品从客户的一句话,做成线上真能用的行业工作台。

你负责

需求对接、建立技术信任、把方案在客户现场落地跑通。

你不越界

价格转商务,竞品不主动谈,不替客户拍业务的板。

怎么算数

验收只代表"当时能跑",30 天使用率才代表"真有人用"。

一条总铁律

以智能体设计为主,平台为辅。 这句话贯穿整个五阶段,别一上来就折腾平台。

01
骨架课 · 后面全挂在这

FDE 五阶段总览

学完能: 复述五阶段一条链,说清每阶段产出什么,分清 2+1 和 3/7/14 两套节奏。

先记一条主线:客户一句话 → 调研备弹 → 沟通挖需求出原型 → 需求确认+智能体设计 → 工作台上线 → 客户试用定稿 → 复制到下个行业。再记一条并行线:进院必备的网络、VPN、部署基础服务(对信息科走)。两条线各走各的,互不等,两线都齐了才交付版本。

打个比方

五阶段像盖楼:阶段一备料进场、阶段二跟业主确认效果图、阶段三把图纸拆成施工方案签字定死、阶段四真盖起来能住人、阶段五业主住进去挑毛病验收。哪步跳过,后面都返工。
客户一句话 ↓ 一、调研准备+备弹知识 → 话术卡+调研SOP(纯知识,无交付物) ↓ 二、需求沟通+原型设计 → 对接确认表+AI能力清单+原型Demo 【2+1 主场】 ↓ 三、需求确认+智能体设计 → 需求最终确认表(签字定稿)+智能体矩阵 【2+1的"1"】 ↓ 四、纳米Work行业工作台 → 能访问的工作台系统+项目进度表 【3/7/14 交付】 ↓ 五、客户试用+智能体优化 → 三轮定稿产品+交付签字+可复制模板 ↓ 沉淀模板 → 复制到下一个行业

两条线并行:环境地基线(绿,对信息科)和需求主线(墨蓝,对业务科室)各走各的,两线齐了才交付版本

两套节奏别讲混

2+1 = 需求侧节奏(数"次")

一轮 = 3 次 = 2 次需求对接 + 1 次签字出原型,落在阶段二三。按次数算,不按天卡;需求大就多跑几轮。

3/7/14 = 签字后开发(算"天")

需求签字 + 环境就绪(两线齐)后进开发,按需求大小 小3 / 中7 / 大14 天,主要在阶段四。

加时赛(外部项目尤其医院):甲方卡住(不签字、不开 VPN、不给接口)就进加时——第一动作发邮件告知甲方留痕,加时时间单独记、不算进版本时间。

当堂练习 + 检查点

  1. 合上教程,白板画出五阶段一条链,每阶段标一个核心交付物。
  2. 判断三个场景各属于 2+1 / 3/7/14 / 加时周期。

过关: 五阶段无遗漏无颠倒,节奏判断全对。

02
新人重灾区 · 从0讲透

医疗行业架构

学完能: 画出医院系统草图,接住核心术语,说清智能体挂在哪个科室。

医疗智能体的燃料是数据,数据都躺在这几个系统里。HIS 是几乎所有业务数据的源头,先记住它。去客户之前就画一张系统草图——哪些数据在系统里、哪些还在 Excel 手工维护,手工维护的地方往往就是痛点。

医院五大系统

HIS 医院信息系统

挂号/收费/开单/药房/住院,业务总台。所有业务数据的源头。

EMR 电子病历

病人诊疗档案。质控、DRG 入组、病历分析靠它。

LIS 检验系统

化验数据:血常规、生化。危急值、指标趋势用它。

PACS 影像系统

CT/MRI/X 光片子和诊断报告。

CDR 临床数据中心

把上面几个系统汇到一起的中央仓库。没有 CDR 取数就难——正是下一课 SDR 要解决的。

怎么用

对着五个系统问:数据在哪个系统?接口啥类型?系统之间通不通?问完就有草图了。

数据流向:HIS 是源头 → 分流到 EMR/LIS/PACS → 全汇到 CDR 中央仓库 → 智能体从 CDR 取数。没 CDR 就得一个个系统接(这就是 SDR 要解决的)

必须听懂的术语(带人话翻译)

术语是什么也就是说
国考三级公立医院绩效考核,55 项指标医院年度大考,排名掉院长最急,最好切入的痛点
DRG/DIP按疾病诊断相关分组付费医保按"病种打包"付钱,入组准不准直接影响收入
CMI病例组合指数科室收的病"难不难",CMI 高=大病多、技术含量高
药占比药品收入占总收入比药费占比,国家要压,太高被考核
平均住院日病人平均住多少天周转效率,住越久床位越紧,医院想压短

现有医疗智能体矩阵

围术期 麻醉科

手术前中后流程与风险、术后监测。

医疗质量 质控

病历质量、诊疗规范,对着国考 DRG 指标。

患者分析 运营

患者画像、分层、随访,有完整 PRD 样板。

运营决策 运营管理部

上海四院样板:心内科"四步归因"(总量→周→亚专业→医生/病人),3 天压到 15 分钟。

人力资源 党办/人事

干部考核、人才盘点、HR 数据分析。

怎么用

接新场景先看矩阵有没有相近的能搬。方法通用、结果定制。

医疗现场铁律

只跟 IT 聊不出业务需求 —— 决策权在业务部门,信息科是给数据的配合方。

业务方向对人 —— 运营分析找运营管理部、围术期找麻醉科、干部考核找党办。

当堂练习 + 检查点

  1. 盲画五大系统 + 数据流向,标出源头和中央仓库。
  2. 老师报术语,你立刻用"也就是说……"翻人话。

过关: 系统草图五个齐、源头标对;术语翻译不愣三秒。

03
藏在背后的地基

技术底座 · SEAF + SDR

学完能: 说清 SEAF 藏在哪、SDR 解决什么,以及"客户只面对一个纳米Work"这句话。

SEAF = 智能体引擎底座

记住一句话:对外只有一个产品——纳米Work 行业工作台;SEAF 只在底层供能力,不单独露面。工作台里的智能体、Skill、知识库、MCP、工作流,都是工作台的入口/组件;它们底层的能力(智能体引擎、工作流、长期记忆、离线大模型)由 SEAF 提供。相当于把 SEAF 封装成工作台的组件,客户从头到尾只用一个工作台。

打个比方

SEAF 像发电厂,纳米Work 工作台像你家墙上的插座和电器。客户只跟插座和电器打交道,不用知道电从哪个发电厂来。

分层架构:客户只看纳米Work(顶层)→ SEAF 引擎在下面供能 → SDR 把底层各业务系统的数据接上来喂进去

SEAF 供什么能力
  • 智能体引擎、工作流编排
  • 长期记忆(让智能体"越用越聪明")
  • 分科室/分角色权限
  • 离线大模型(数据不出院)
  • L2/L4 分层调用能力
为什么不露面

客户只面对纳米Work 一个入口,体验统一、好复制。SEAF 的欠账(长期记忆、分权、审计埋点)由平台统一跟进,别分散在各项目重复提。

SDR = 数据地基

智能体要跑起来靠数据,可商业化项目全卡在同一个地方——数据太多、太乱、拿不出来。一个客户少则三五个业务系统,多的十几个;每家厂商字段名还不一样;客户又不愿意开数据库直连。结果每接一个客户都要重写一遍对接代码,耗在数据上的时间比做智能体还多。没数据 → 智能体是空壳。

卡点SDR 怎么解
每个客户重写对接代码通用连接器 + 配置映射,零代码接入
字段名各家不同映射层统一成标准字段,智能体侧零改动
客户不给直连只读客户授权的 View,数据不出内网
云端进不了内网SDR 主动出站连云端,客户不用开端口

底座铁律

SDR 不是锦上添花,是智能体商业化的地基 —— 数据这关过不去,后面所有项目都推不动。

对客户只有一个纳米Work —— SEAF 藏底层供能,别在客户面前拆开讲。

当堂练习 + 检查点

  1. 用发电厂的比喻,给同伴讲清 SEAF 和纳米Work 的关系。
  2. 说出 SDR 解决的四个卡点各对应哪个解法。

过关: 能讲清"客户只面对一个产品";四个卡点对应无错。

04
阶段一二三 · 最核心技术阶段

需求与智能体设计

学完能: 用六项框架挖需求、四把钥匙撬隐性经验、五层拆解法把业务拆成可执行的智能体。

阶段一:备弹进场(纯知识)

进场前把弹备足:行业政策、术语、痛点、组织关系摸清,练调研话术。这阶段没有交付物,练的是"怎么聊"的内功。先问后讲、让客户自己说——痛点从甲方嘴里出来他才认账。

72 小时作战地图(前三天怎么打) Day 0 备弹(行业知识+业务调研+组织与人+基础方法) → Day 1 破冰(启动会+摸组织关系) → Day 2 深挖(六项框架挖需求) → Day 3+ 拉齐(收敛对齐+出原型)

阶段二:沟通出原型

带话术进场,第一轮先启动、摸清五层关键人(谁拍板/谁负责/谁配合数据),填进《对接确认表》。每轮沟通当场发群确认(群确认等同签字)。再把确认表喂给产品设计专家智能体出原型,约 3 小时一版。

六项调研框架

目标 / 要什么 / 痛点 / 价值 / 业务流程 / 数据流程。业务流程要拆到每个节点的输入输出。

四把钥匙(撬隐性经验)

吐槽法 / 场景重现 / 如果法 / 反面教材。业务规则直接问、数据找 IT 要、隐性经验靠激不靠问。

阶段三:签字定稿 + 拆智能体矩阵

先把需求收敛成《需求最终确认表》签字定死,再把一条业务链路拆成智能体矩阵——一个环节一个专用智能体,各管一段、首尾相接。每个智能体照设计表走。

五层拆解法(把业务专家的隐性经验拆成可执行结构) Workflow(整体流程) → 节点数据流 → Playbook(规则) → 边界(管到哪) → 异常(出岔子怎么办) ↓ 映射到 Agent 六组件:角色 / Prompt / 知识库 / 技能 / 工具 / 记忆 ↓ 写 Prompt → 编排 Skill → A/B 测试 → 过 Eval 门禁(准确率≥90%) 才上线

从拆解到上线三层:五层拆解(红色"异常"最易漏)→ 映射进六组件 → 调优后过 Eval 门禁(≥90%)才放行

举个真实例子:心内科"四步归因"

别停在概念上,看四院这个样板怎么落地。科室主任的痛点是:每月运营数据掉了,查原因靠人一层层翻,要花 3 天。拆成智能体后压到 15 分钟。它的 Workflow 就是一条"四步归因链路"——层层往下钻,每步缩小范围。

心内科运营归因(把 3 天压到 15 分钟) 第一步 看总量(哪个指标掉了) → 第二步 拆到周(哪一周开始掉) → 第三步 拆到亚专业(哪个方向的问题) → 第四步 拆到医生/病人(定位到具体人/病例) 每步都是"缩小范围"的一次追问,正好对应五层里的 Workflow + 节点数据流

核心铁律

需求先签字再设计 —— 猜错一条后面全返工。

边界和异常最容易漏 —— 正常路径谁都会写,异常兜底和转人工才是上线不翻车的关键;准确率≥90% 不达标不放行。

当堂练习 + 检查点

  1. 拿一个假场景("科室想看月度运营"),用六项框架列出该问哪些问题。
  2. 把这个场景用五层拆解法拆一遍,标出边界和异常。

过关: 六项框架不漏项;五层里边界、异常都写到了。

05
阶段四 · 最易失控的一步

行业工作台

学完能: 说清工作台是什么、技术栈为什么锁死、五步走怎么把智能体挂上去跑起来。

阶段四把阶段二的原型、阶段三的智能体矩阵,变成客户能访问、能用、能上线的行业工作台。靠技术栈锁死 + 统一 skill 保证能复制到下一个行业。阶段四不重新设计智能体,只把设计好的挂上去跑起来。

纳米Work 是什么

"360 纳米Work 行业 AI 工作台",三个可独立部署的服务:API / Scheduler / 前端,多租户权限底座 + 任务调度引擎。

技术栈锁死

后端 FastAPI+SQLAlchemy 2.0+Pydantic 2;前端 Vue3+TS+Vben Admin。多租户强制 hospital_id 过滤。技术栈一乱,复制就无从谈起。

工作台五步走:建模 → 后端 → 前端 → 联调(真实数据)→ 上线(极库云→容器云给 URL)

怎么约束 AI 别乱写:平台沉淀了 64 个标准 skill(api-* 32 个 + vben-* 32 个),三层门禁把关——铁律(CLAUDE.md)+ 规范库(按任务触发)+ 门禁(redline-guard 静态检查 + CI 硬拦截)。照规范生成,不从零手写。

工作台铁律

上游给垃圾,下游出精致的垃圾 —— 功能清单缺"关联智能体/数据依赖",实现岗有权打回。

建模不通不许往下走,跑真实脱敏数据找断点,不是 mock;先 demo 后完整,别一口气憋大的。

  1. 背出五步流程和每步对应的 skill。
  2. 说清为什么技术栈必须锁死、多租户为什么强制 hospital_id。

客户试用与优化

三轮递进定稿

三轮定稿像漏斗:第一轮看方向 → 第二轮抠细节 → 第三轮定死。验收标准一轮比一轮严

一、五类规范(守什么规矩)

这五类规范别当五个名词背——它们是按项目推进顺序卡在不同节点上的。从签字前到交付后,一条线走下来,每个节点该守哪条规矩,看下面这张时间线就清楚了。

项目推进时间线 · 每个节点卡一道规矩 签字前 交付规范(边界阶段一定死·72h签字制) → 设计时 设计规范(五层拆解→六组件→Eval) → 开发中 质量规范(每节点检查·卡住不许往下) → 要交付 验收规范(三条硬标准) → 交付后 复制规范(沉淀模板) + P0–P3 SLA(出问题分级响应)
规范卡在哪核心要求
交付规范签字前每阶段有明确输入/输出/责任人;输出必须成文档;交接干净不掉链子;边界阶段一就签字定
设计规范设计时照《智能体设计标准模板》:五层拆解→六组件→Prompt→Skill→A/B→Eval 门禁
质量规范开发中准确率≥90% 才放行;每节点检查输出完整性,卡住不许往下;三轮定稿;全流程 Trace 可回放
验收规范要交付三条才算交付完成:①经过三轮定稿 ②准确率达标 ③业务方确认可用;交付后沉淀成模板
复制规范交付后方法通用、结果定制;团队要覆盖六种能力(业务/智能体/AI编程/技能/知识库/连接器)

时间线上有三个"闸口"要特别记住——它们是最容易踩坑、也最能防返工的地方:

72h 签字制 签字前

产品原型阶段用 72 小时签字制卡返工:不签字不开工。需求没定死就动手,后面全返工。

三个人工确认节点 全程

原型签字 / 建模评审 / 合并审核。其余交给 AI 自主运行,只在这三处人工把关。

P0–P3 响应 SLA 交付后

P0 30 分钟响应/当天修,往下按级递减到 P3 一周评估。每条 P0/P1 做响应三件套:复现定位(Trace)+ 最小改动(改完跑评测集)+ 客户回执。

二、角色分工 + 五阶段在极库云怎么落

FDE 项目经理 规划

负责迭代版本的规划、需求和任务的创建。把用户需求拆条、排优先级、规划进哪个版本。

FDE 交付 执行

根据产品需求做任务拆解,在迭代版本的时间范围内完成。每天定期更新需求任务。

五阶段项目管理落到极库云,一共六项要管起来。前两项照五阶段走(需求沟通+原型、需求确认+智能体设计),后面四项是极库云上要额外产出/维护的:

五阶段项目管理 · 极库云上要管的六项 ① 需求沟通 + 原型设计 ② 需求确认 + 智能体设计 ③ 产品实施计划说明书(定位产品复制模式) ④ 工作日报(按月建文件·按天竖排) ⑤ 工作周报(按季度建文件·按周竖排) ⑥ 相关材料(录音/客户资料/竞品调研)
①② 前两阶段

照五阶段照旧走:需求沟通+原型设计、需求确认+智能体设计。产出对接确认表、原型、需求最终确认表、智能体设计表。

③ 产品实施计划说明书

定位到产品复制模式,由项目经理和交付共同完成。举例 HIS 厂商的标品交付 SOP:①账号开通 → ②数据治理 → ③智能体调试 → ④平台调试 → ⑤客户试用。

④ 工作日报

按月新建文件,按天竖排。一个月一个文件,每天一条往下排。

⑤ 工作周报

按季度新建文件,按周竖排。一个季度一个文件,每周一条往下排。

⑥ 相关材料归档

录音、客户资料、我们调研的竞品材料,统一归档到项目下。

三、项目需求管理(拆需求 → 排版本 → 盯进度)

核心是把需求拆条、规划进迭代版本、盯着交付每天更新。以"医疗质量风险管理"为例,把用户最终的 10 个需求,在极库云需求管理里逐条拆成 10 个,再规划到 3 个版本里,按优先级分:

迭代版本优先级装什么需求
医疗质量分析管理 v1.0.0P0最核心、必须先上的需求
医疗质量分析管理 v1.0.1P1次要、第二批做的需求
医疗质量分析管理 v1.0.2P2可以往后放的需求

需求管理流程:用户需求 → 极库云拆条 → 排进迭代版本(P0/P1/P2)→ 交付拆任务日更 → 两个平台看成果

交付拿到需求后做任务拆解,在版本的时间范围内完成。项目经理每天盯交付的任务执行情况,或者拉一个专项群让交付定期同步进度。进度和成果从两个地方看:

看需求成果

从 aimed.mss.360.net 纳米Work 医疗行业工作台里看做出来的东西。

看智能体成果

从 SEAF 智能体平台里看智能体编排成果(项目经理和交付一起完成的)。

四、产品复制模式(标品 / 定制化)

同一套产品复制到新客户,分两种模式走,别混。

① 标品模式

有一份标品实施部署说明书(项目经理和交付共同完成)。在极库云创建需求、规划进迭代版本(比如 7 天),照 SOP 走并跟进项目。走得快、能复制。

② 定制化模式

又分两种:新增需求(共性、通用性功能)——可做;完全定制——先评估工作量和预算,再决定要不要做。两种定制都要重新走 FDE 五阶段,从需求到交付。

复制模式决策:先判断是不是标品 → 是就照说明书快走;不是就看定制类型(通用需求可做 / 完全定制先评估)

项管铁律

输出成文档、设计有模板、上线过门禁、验收有标准、复制留模板 —— 每一步都有规矩,不靠拍脑袋。

需求先拆条、排版本、定优先级 —— 10 个需求拆 10 条,按 P0/P1/P2 装进不同版本,别一锅端。

交付每天更新任务,项目经理每天盯 —— 进度靠日更盯出来,不是等到 deadline 才发现没做完。

完全定制先评估再接 —— 通用功能可做,完全定制先算清工作量和预算,值不值得再决定。

当堂练习 + 检查点

  1. 背出五类规范和验收的三条硬标准,说清三个人工确认节点卡在什么时候。
  2. 给一个假项目("某院要 8 个需求"),拆条并规划进 2–3 个版本、标 P0/P1/P2。
  3. 判断三个新客户场景各该走标品、新增需求、还是完全定制。

过关: 五类规范说全、验收三条不漏;需求拆条清晰、优先级合理;三个复制场景判断对。

项目实战演练

场景剧本:教练智能体扮客户

教练智能体扮三种人设,脾气各不同:科室主任(要结果、没耐心)、信息科(担心数据安全、给数据抠)、临床医生(嫌麻烦、说不清需求)。学员用四把钥匙一点点撬需求。

阶段要干的事产出物
阶段一 备弹研究场景、备术语、画组织地图调研准备(话术+组织地图)
阶段二 挖需求跟教练客户对话挖需求、喂智能体出原型对接确认表 + 原型 Demo
阶段三 定稿+拆矩阵需求签字定稿、拆智能体矩阵、五层拆解需求最终确认表 + 智能体设计表
阶段四 出 demo建模→前后端→联调,把智能体挂上去能演示的 demo 系统

五维计分卡(答辩加权打分)

考核不看单一指标,五个维度加权。后两项(产品化贡献+知识沉淀)占 30%——交付完不算完,得给整个体系留下东西。通过率控在 60–70%,宁可少发证别发错证。

维度权重看什么
交付效率20%场景从头到尾花了多久,有没有拖、有没有该发邮件留痕的没发
验收通过率25%客户签字验收一次过,还是反复返工;准确率是否≥90%
30 天使用率25%交付完 30 天,客户还在不在用
产品化贡献15%有没有沉淀出可复用的 Skill / 模板
知识沉淀15%有没有把踩的坑、行业知识写进知识库

③ 结果防线
