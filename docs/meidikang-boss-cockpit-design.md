## 0. 需求原文(甲方:美迪康)

美迪康采购 AI 办公软件的核心诉求:

- **打通各部门协同**,把各部门的工作**串起来**。
- 作为最高管理者的老板,能像看**经营驾驶舱**一样,随时知道:
  谁在做什么、做到哪了、质量怎么样、哪里卡住了、哪些事情需要最高管理者介入。
- **工作现状**:全员已在用各类 AI 工具,但分散独立、碎片化,缺乏统一协同与管理。
  - 程序员 → **Trae**(代码开发)
  - 市场、销售 → **豆包、DeepSeek** 等通用大模型
  - 售前、工程 → **龙虾、QClaw** 等
- 因此计划采购**一体化 AI 办公平台**。
- (甲方补充)需要一个 **AI 网关**,管控 **token 使用/成本**。

---

## 1. 核心设计哲学:三层定位

> **工具是"手",网关是"卡口",平台是"大脑和账本"。**

关键定位(经与甲方多轮澄清后确定):

> **平台本身就是全员唯一工作台**。不是去对接/收口外部一堆工具,而是让大家都进到这**一个平台**里干活 —— 程序员在「代码模式」写代码、市场/销售用「专家广场」、售前用「对话」。
> 于是老板驾驶舱的数据 = **平台自己产生的**,天然完整,无需外部对接。

| 层 | 角色 | 解决什么 |
|---|---|---|
| **AI 网关层** | 卡口 | 所有 AI 调用必经之路 → token/成本管控 + 数据收口 + 安全审计 |
| **统一工作台** | 全员入口 | 各部门都在此干活,产出天然沉淀 |
| **跨部门任务流** | 协同骨架 | 任务带上下游,一棒交一棒,把工作"串起来" |
| **老板驾驶舱** | 大脑 | 自动汇聚 + AI 质量评估 + 主动预警 |

平台**已具备**全员所需的"通用平台工具",无需新建:

**结论**:全员用的通用工具平台里都有了 → 只需**新增两块**(AI 网关 + 老板驾驶舱)+ **补一层**(跨部门任务流)。

**网关是关键**:让"收口"从"求大家配合上报"变成"不走网关就用不了 AI"。数据、成本、审计,全在这一层自然沉淀。

### 3.1 支撑地基(经全覆盖体检补入,让架构经得起追问)

主线 4 层之下,还有 3 块**地基**——不是新需求,而是支撑现有各层、经得起老板与 IT 追问的底座:

| 地基 | 解决的追问 | 作用 |
|---|---|---|
| **企业知识数据底座** | "AI 凭什么懂我们医疗业务?" | 私有知识库/业务数据沉淀,让专家广场不是空壳,回答/产出有企业上下文 |
| **组织与权限体系** | "驾驶舱给谁看?员工能看到全公司吗?" | 组织架构 + 权限分级:老板看全公司、部门经理看本部门、员工看自己;贯穿所有层 |
| **安全合规 / 私有化** | "医疗数据出不出去?能私有化部署吗?" | 数据不外泄、调用可审计、支持私有化部署;医疗行业刚需 |

完整分层(自上而下):

```
①  老板经营驾驶舱(大脑)         ← 谁看:老板/管理者(权限分级)
②  跨部门协同流(协同骨架)
③  统一 AI 工作台(全员入口)
④  AI 网关(卡口:token/成本/审计/路由)
⑤  企业知识数据底座 + 安全合规 / 私有化(地基)
        └ 底层多模型:自研 / 豆包 / DeepSeek / ...
   [贯穿右侧竖条:组织与权限体系]
```

## 4. 老板驾驶舱首屏(5 大模块)

按老板视线动线,从上到下:

### ① 顶部 — 经营/效率指标条(一眼看健康度)
- 本月 AI 调用量 / Token 消耗 / 折算成本(↑↓ 环比)
- 全员 AI 使用率、跨部门协同任务数、平均任务周期
- 人效提升估算(AI 替代的工时)

### ② 左主区 — 各部门任务进展(谁在做什么、做到哪)
- 部门泳道视图:每个部门下的任务卡片
- 每张卡:任务名 / 负责人 / 进度% / 状态(正常·预警·卡点)/ 最近产出
- 颜色编码:绿=正常,黄=需关注,红=卡点/超时

### ③ 右上 — 需老板介入事项(主动推到面前)
- AI 主动识别:超时、卡点、跨部门冲突、需决策审批
- 每条带"为什么需要你" + 建议动作 + 一键处理

### ④ 右下 — 工作质量评估(不只看做没做完)
- AI 对各部门产出打分(内容质量 / 规范性 / 完成度)
- 质量趋势 + 低分产出下钻

### ⑤ 跨部门协同流(★ 需求核心:把工作"串起来")
- 一条横向价值链视图:**市场→销售→售前→研发→工程**
- 红点标出:**卡在哪一棒、堵了谁、等了多久**
- 这才是老板真正要的"打通协同 / 看哪里卡住"——
  不是孤立看每个部门做没做完,而是看**接力棒有没有顺畅传下去**。
  例:"售前方案卡了 3 天 → 研发空等" 一眼可见。

## 5. 每个指标怎么来(数据来源)

| 老板想看 | 数据从哪来 | 怎么拿到 |
|---|---|---|
| 谁在做什么 | 任务协同层 | 平台派发的任务天然带负责人/部门 |
| 做到哪了 | 执行跟踪 | 任务状态流转 + AI 从产出推断进度 |
| Token/成本 | **AI 网关** | 每次调用自动计量,按部门/人/任务归集 |
| 质量如何 | **AI 评估引擎** | 产出回收后,AI 按标准自动打分 |
| 卡在哪 | 规则 + AI | 超时/无更新/依赖阻塞 自动识别 |
| 跨部门卡点 | **跨部门任务流** | 任务上下游关系 → 定位断棒 |
| 需你介入 | 主动预警 | 卡点/冲突/决策项 主动推送 |

**三路汇聚 = 老板全貌**:网关拿成本,协同层拿进展+跨部门流转,AI 引擎拿质量。

## 6. AI 如何自动评估"工作质量"(差异化亮点)

老板最怕"任务显示 100% 完成,但产出是垃圾"。质量评估是灵魂:

- **产出回收即评估**:文档/代码/方案回收到平台,AI 自动按部门标准打分
  - 市场文案 → 品牌调性/传播力/合规
  - 售前方案 → 完整度/专业度/客户匹配
  - 研发代码 → 规范/缺陷风险
- **异常主动上报**:低分产出、疑似敷衍、前后矛盾 → 进"需介入"
- **可下钻**:老板点开看 AI 为什么给这个分,附原文
