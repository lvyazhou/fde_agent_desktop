FDE 入职作战手册 · 前线交付工程师

把弹备足，进场，
把智能体跑成客户真在用的系统。

FDE（Forward Deployed Engineer，前线交付工程师）不签单、不谈价，做的是三件事：需求对接 · 技术信任 · 方案落地。 从进客户门那一刻起，你要走完一条五阶段的实战路径 —— 这一页是它的地图。

备弹进场→ 沟通出原型→ 拆智能体矩阵→ 搭行业工作台→ 试用定稿盯使用率
你负责
需求对接、技术信任、把方案在客户现场落地跑通
你不越界
价格转商务，竞品不主动谈，不替客户拍业务的板
怎么算数
验收只代表"当时能跑"，30 天使用率才代表"真有人用"

五阶段路径

01调研准备 · 备弹知识 02需求沟通 · 原型设计 03需求确认 · 智能体设计 04纳米Work 行业工作台 05客户试用 · 智能体优化
01
调研备弹 · 纯知识内化

调研准备 + 备弹知识

读规范 → 背备弹 → 练框架 → 带话术。进客户门之前就把弹备足，练到条件反射。这一阶段没有交付物，练的是"怎么聊"的内功。

你要做什么

  • 背熟备弹知识：行业政策、术语、六大痛点带全国数据、对标案例带量化
  • 练透六项调研框架 SOP，配五层拆解法一层层钻到底
  • 练熟话术，把七种咨询/控场方法带进现场

交付物 交付

无 —— 阶段一不填表、不签字

产出是"内化产出"：张口能接的备弹、烂熟的调研框架、条件反射的话术。

核心装备

备弹知识库

进场前背熟政策（国考/DRG/CMI/药占比）、术语、六大痛点与对标案例，做到与客户同频。

六项调研框架 SOP

目标 / 要什么 / 痛点 / 价值 / 业务流程 / 数据流程，保证聊全不漏项；业务流程要拆到每个节点的输入输出。

SPIN + 七维引导

情境→痛点→影响→需求回报；核心信息→目标→现状→痛点→业务流程→数据流程→验收，前一维答案自然引出下一问。

七种控场方法

STAR / 5W1H / 量化锚定 / 吐槽法 / 场景重现 / 如果法 / 反面教材；控场三招：关键词桥接、价值锚定、白板牵引。

FAB + AI 价值翻译

把 LLM/RAG/多智能体/OCR 等技术能力翻译成甲方听得懂的业务价值，每个技术词后跟一句"也就是说……"。

四步澄清法

客户说不清需求时：接住 → 翻译给场景菜单 → 具象"谁+做什么+多久" → 量化。

铁律 · 记在脑子里

备弹是最关键一环 —— 第一印象搞不定，后边再努力得几百倍。

先问后讲、让客户自己说 —— 痛点从甲方嘴里出来他才认账。

业务规则直接问、数据资产找 IT 要、隐性经验靠激不靠问；只跟 IT 聊不出业务需求，决策权在业务部门。

02
沟通 · 原型

需求沟通 + 原型设计

第一轮先启动、先摸组织关系 → 多轮沟通挖需求、对齐 AI 能力 → 出原型 → 用能看能点的原型把需求收敛对齐 → 交棒阶段三签字定稿。

你要做什么

  • 第一轮 = 启动会 + 摸清五层人（谁拍板/谁负责/谁配合数据）
  • 分轮沟通，每轮当场发群对齐（群确认等同签字）
  • 把确认表 + 能力清单喂"产品设计专家智能体"出原型，约 3 小时出一版

交付物 交付

需求与数据对接确认表（含组织关系） AI 需求能力清单 产品原型 Demo（含 PRD 三层）

节奏"2+1"主场：一轮=2次需求对接+1次确认出原型，按次数算不按天卡。

核心方法

先摸组织关系

当场摸清五层人（院长/总经理→分管副总→部门主任→操作员→信息科），直接填进对接确认表。人没对齐就往下聊，聊到验收才发现拍板人是另一个。

原型驱动收敛

很多说不清的需求，客户看到能点的东西才反应过来"对/不对"，用原型一轮轮磨到方向认可。

FDE 专属产品设计专家

统一用它出 PRD + 原型，内部自动跑结构化拆解、PRD 三层、信息架构、六区块生成。别散着拼提示词。

AI 能力量化可验收

每个能力写清输入/输出/效果指标（如"问数≤30秒/准确率≥95%"）/验收口径/异常处理，不写"好用""智能"。

功能清单六字段

功能名/所属页面/描述/优先级/关联智能体/数据依赖 —— 后两项是进入阶段三的红线，也是阶段三智能体矩阵设计的输入。

两层签字别混

阶段二是"每轮当轮确认"（群确认等同签字）；阶段三才把收敛后需求上《需求最终确认表》总签定死。

铁律 · 四条

第一轮先启动、先摸组织关系；原型驱动需求收敛，别指望上来就签死。

原型统一用 FDE 专属产品设计专家 —— 智能体出的交付物才标准、可复制。

AI 能力要量化、可验收；一进加时先发邮件留痕，防扯皮。

03
需求确认 · 智能体设计 · 最核心技术阶段

需求确认 + 智能体设计

需求签字定稿 → 拆智能体矩阵 → 逐个照设计表填 → 配六组件 → A/B 调优 → 过 Eval 门禁上线。一个环节一个专用智能体，各管一段首尾相接。

标准动作 · 六步

  • 需求签字定稿（确认表/任务计划/验收标准跟客户签死）
  • 拆矩阵：一个环节一个智能体，不越界不重叠
  • 逐个照 1 号设计表填：身份卡 → 五层拆解 → 六组件
  • 用 A/B 测试挑最优提示词，过 Eval 门禁才上线

交付物 交付

智能体设计表 需求最终确认表 项目任务计划表 项目验收标准表 产品需求文档 PRD
核心标准模板

智能体设计表 核心 · 一体一份

八部分自包含。五层拆解（Workflow→节点数据流→Playbook规则→边界→异常）是核心，把业务专家隐性经验拆成可执行结构。

PRD 产品需求文档

阶段四建模与验收的直接依据。第七章功能清单六字段缺一不可，"关联智能体""数据依赖"是红线；签字后走变更记录，不口头改。

提示词工程

六要素结构：角色/任务/输入/规则/输出格式/约束。规则从五层拆解搬，不拍脑袋写；用 Git 管版本，一体一个 prompt.md。

技能 Skill

单一职责·错误处理·命名规范·可复用。优先用平台 64 个标准 Skill（api-*32 + vben-*32），能复用别自研；简单≤3秒/复杂≤10秒。

连接器 Connector

工具（原子能力）vs 连接器（对接外部系统的桥接层）。推荐 MCP 协议，自定义走 DataHub MCP APIHub + 纳米Work，配置六步含异常/超时/降级。

知识库配置

内部/行业/外部三类型。数据质量四条：权限（科室 Agent 不看全院）、时效、结构（按层级/条款/语义切片，不按固定字数切）、安全（脱敏可追溯）。

A/B 测试

四维度对比：提示词写法/工作流编排/知识库范围/Skill 配置。用真实数据≥10 用例跑，记录准确率+理由+业务方签字。

Eval 评测 · 上线门禁

达标线：准确率≥90% / 召回率≥85% / 精确率≥90% / F1≥87% / 响应≤10秒。用例配比 正常60% / 边界20% / 异常20%。

根本铁律

以智能体设计为主，平台为辅。

需求先签字再设计 —— 猜错一条后面全返工；一个环节一个智能体，数据流首尾闭环。

边界和异常最容易漏 —— 正常路径谁都会写，异常兜底和转人工规则才是上线不翻车的关键；准确率≥90% 不达标不放行。

04
工作台上线 · 最易失控的一步

纳米Work 行业工作台

把阶段二的原型、阶段三的智能体矩阵，变成客户能访问、能用、能上线的行业工作台。靠技术栈锁死 + 统一 skill保证能复制到下一个行业。

五步标准流程

  • ① 建模（api-er-modeling）→ ② 后端（api-guide）
  • ③ 前端（vben-guide）→ ④ 联调（走 requestClient，跑真实数据非 mock）
  • ⑤ 上线（极库云流水线 → 360 智汇云容器云，给可访问 URL）
  • 两步交付：先 demo 验方向，后完整（P0+P1+异常+权限+部署）

交付物 交付

ER 模型图（数据验证过） demo 版系统 完整前后端工作台 部署文档 源代码（无硬编码密钥） 项目进度表（甘特图）

本阶段【交付】主体是能跑的系统本身。节奏 3/7/14 天版本主场，等甲方时间算加时周期单独记。

核心知识点

纳米Work 是什么

"360 纳米Work 行业 AI 工作台"（代号 ai-work-platform），三个可独立部署的服务：API(8100) / Scheduler(8101) / Frontend，多租户权限底座 + 任务调度引擎。

技术栈锁死

后端 FastAPI+SQLAlchemy 2.0(async)+Pydantic 2；前端 Vue3+TS+Vben Admin 5+Element Plus。多租户强制 hospital_id 过滤。技术栈一乱，复制就无从谈起。

64 skill + 三层门禁

.claude/skills 沉淀 64 个 skill；铁律(CLAUDE.md) + 规范库(按任务触发) + 门禁(redline-guard 静态检查 + pre-commit/CI 硬拦截)约束 AI。

ER 建模三步 + 数据演练

实体识别 → 关系建模（四维校验）→ 灌真实脱敏数据走核心流程找断点。脏数据、缺字段才是上线后真正的坑。

智能体接入规范

智能体与引擎解耦：一体可挂多引擎（SeaFactory 主力 + Dify），每引擎一 adapter，调用落 log_mcp_queries。标配三页：管理页/测试页(SSE)/工具箱页。

职责不混

智能体设计归阶段三、工作台实现归阶段四。阶段四不重新设计智能体，只把设计好的挂上去跑起来。

铁律

上游给垃圾，下游出精致的垃圾 —— 功能清单缺"关联智能体/数据依赖"，实现岗有权打回。

AI 编程工具是放大器，不是造物主；建模不通不许往下走，跑真实数据，不是 mock。

先 demo 后完整 —— 别一口气憋大的。

05
试用 · 定稿 · 盯使用率

客户试用 + 智能体优化

在能跑的工作台上，通过真实试用 + 三轮迭代，完成从"能跑"到"定稿成型"，并沉淀可复制的行业模板。两条主线：跑稳跑准跑出价值，建立"反馈—响应"闭环。

你要做什么

  • 组织客户试用，跑三轮递进式定稿
  • 四渠道收反馈 + 一张表闭环，工程化优化智能体
  • 上线后盯 30/60/90 天使用率，打包行业模板

交付物 交付

客户反馈跟踪表 三轮迭代记录表 使用率盯防表 项目交付签字表

建议周期 2–4 周。产出定稿产品 + 可复制行业模板。

核心机制

三轮递进定稿

第一轮看大方向 → 第二轮抠细节（逻辑/字段）→ 第三轮定死（体验交互+全量回归）。问题粒度从粗到细，验收标准从松到严。

四渠道 + 一张表

现场陪跑（头3天）+ 答疑群 + 埋点异常告警 + 周度复盘。反馈按功能缺失/逻辑不通/体验问题三类分流，走登记→分类→响应→验证→归档五步。

响应分级 + 三件套

P0 30分钟/当天修 … P3 一周评估。每条 P0/P1 必做响应三件套：复现定位（Trace）+ 最小改动（改完跑评测集）+ 客户回执。

优化工程化闭环

问题定位→口径对齐→最小改动→对照验证→兜底补强→沉淀复用。样板：心内科归因智能体 A/B 10 病例 72%→91%。

30/60/90 盯防

30天抓小问题、60天看真实活跃率（掉了一线回访）、90天收新需求评二期看留存。

可复制行业模板

不换（通用方法）：四步标准法/五层拆解/三轮定稿/平台还原。要换（行业定制）：业务知识/ER模型/数据源/行业 skill/知识库。

铁律 · 收官

验收通过只代表"当时能跑"，30 天使用率才代表"真有人用"。

优化不是玄学调 Prompt，而是工程化闭环；结果错是硬伤，体验差是软伤，先保硬伤。

响应三件套缺一件视为未闭环；每条反馈必须写明根因，禁止只写"已处理"；同类问题≥3 次触发专项复盘。
