# 庄重商务架构图生图

用于生成适合医院、信息科、院领导和正式汇报场合的商务架构图。核心要求是：**白底、深蓝系、分层清楚、内容均衡、气质庄重**。调用现有 `image-generator`，不要改用 SVG 手画，也不要改成赛博朋克或海报风。

## 固定视觉合同

- 画布固定为 `1792x1024`。
- 质量固定为 `high`。
- 背景使用白色或极浅灰蓝。
- 只用深蓝、藏青、钢蓝、浅灰蓝、白色。
- 严禁红色、黄色、橙色、金色、紫色、暖色、霓虹、发光渐变。
- 视觉气质：庄重、端正、克制、专业、适合医院信息化和院领导正式汇报。
- 不要人物、营销海报、赛博朋克、游戏 UI、复杂纹理、装饰性光球。
- 所有模块用白底卡片、细深蓝边框、统一圆角和一致间距。

## 固定布局合同

默认采用“左侧三层架构 + 右侧三道安全防线”的构图：

1. 顶部放完整标题和副标题。标题必须使用用户给出的原文，不得自行缩写或替换。
2. 左侧主区使用三张独立、等高、边缘对齐的层级卡片，不要画成三条简单横色带。
3. 三层顺序固定为：工作台层（顶部）、SDR 数据基座（中部）、数据层（底部）。除非用户明确要求，不得新增第四层或第五层。
4. 左侧增加贯穿三层的深蓝纵向主轴，用编号和层名标出层级；主数据流沿主轴自下而上。
5. 工作台层必须画出蓝色虚线大框，并在左上角清晰标注“360 私有云”。
6. 工作台层必须保留“业务数据阅后即焚”标签；没有这项要求时，也不要擅自删除用户已提供的安全约束。
7. 中部 SDR 层拆成服务网关层、服务平台层、数据治理层三个等宽子模块。
8. 底部数据层放 Oracle 业务库和自建 HR MySQL 两个等高数据源卡片；HR 旁路用钢蓝虚线进入服务平台层。
9. 右侧独立放三道等高安全面板：数据安全、大模型安全、智能体安全。
10. 所有区域要均匀填充画布，模块等宽对齐，左右视觉重量平衡；不能一侧信息拥挤、另一侧大片空白。

## 内容保真规则

- 用户提供的标题、层级名、系统名、模块名和安全承诺必须原样保留。
- 不要为了“画面好看”自行改写业务名称、删减模块或新增业务层。
- 专有名词照原文保留：`纳米Work`、`360 私有云`、`Seaf`、`SDR`、`SeaTunnel`、`Apache Doris`、`Oracle`、`MySQL`、`MCP`、`HTTP`、`WebSocket`、`TLS`。
- 四大业务方向及智能体名称有明确输入时，必须逐项写入；不能只写数量。
- 生成前检查：标题、360 私有云、业务数据阅后即焚、三层、三道防线、HR 旁路是否都出现在提示词中。

## Prompt 组装方式

把用户内容放进下面骨架，不要只写“做一张商务架构图”：

```text
白色背景，庄重大方严肃商务风格，适合正式汇报。全图只使用深蓝、藏青、钢蓝、浅灰蓝和白色，不使用红色、黄色、橙色、金色、紫色、暖色和霓虹光。画布为1792x1024，内容均匀填充，模块等宽对齐，左右密度均衡，无大块空白。

顶部完整标题：{用户标题}
副标题：{用户副标题}

左侧为三层独立卡片式安全架构，使用贯穿三层的深蓝纵向主轴和自下而上的数据流：
工作台层：{工作台内容}。必须画出蓝色虚线大框，左上角明确标注“360私有云”。{阅后即焚要求}
SDR数据基座：服务网关层{网关模块}；服务平台层{平台模块}；数据治理层{治理模块}。
数据层：{Oracle数据源}；{HR MySQL数据源和旁路规则}。

右侧为独立的三道安全防线面板：数据安全{内容}；大模型安全{内容}；智能体安全{内容}。

风格：企业级咨询报告架构图，白底深蓝系，卡片整齐、线条清楚、层级端正、信息密度均衡、适合医院院领导和信息科正式汇报。所有文字使用中文标签。
```

## 命令规范

Windows 下调用时使用 UTF-8 环境变量，并固定尺寸和质量：

```bash
PYTHONIOENCODING=utf-8 python C:/Users/lvyazhou/.product-lobster/skills/image-generator/generate_images.py \
  -p "{组装后的完整中文提示词}" \
  -s 1792x1024 -q high \
  -d "{输出目录}" -o "{文件名}.png"
```

文件名建议使用版本号，例如 `上海四院纳米Work安全架构_商务v3.png`，不要覆盖用户之前的版本。

## 生成前检查

- [ ] 标题与用户原文一致。
- [ ] 画布为 `1792x1024`，质量为 `high`。
- [ ] 明确写入“360 私有云”虚线大框。
- [ ] 明确写入“业务数据阅后即焚”（用户要求时）。
- [ ] 只保留深蓝系，没有红、黄、橙、金、紫和暖色。
- [ ] 三层顺序正确，没有擅自增加层级。
- [ ] 左侧三层卡片等高、对齐、内容均衡。
- [ ] 右侧三道安全防线独立且完整。
- [ ] 工作台中的业务方向和智能体名称没有被概括成只剩数量。

## 常见失败与修正

| 失败表现 | 修正方式 |
|---|---|
| 没有标题 | 在提示词开头单独写“顶部完整标题：...” |
| 360 私有云消失 | 写“必须画出蓝色虚线大框，并在左上角明确标注” |
| 左侧一边空一边满 | 写“三张等高卡片、等宽模块、边缘对齐、内容密度均衡” |
| 出现红色、黄色或金色 | 在开头和结尾各写一次禁用色约束 |
| 生图擅自增加五层 | 明确写“三层，且不得增加其他层级” |
| 方向名称被改写 | 写“用户提供的名称必须原样保留，不能只写数量” |
| 画面变成赛博朋克 | 同时写“白底商务咨询报告风格”和“无霓虹、无发光、无复杂纹理” |

## 结果说明

生图模型对中文小字、精确连线和模块数量仍可能出现偏差。生成后应让用户重点检查标题、360 私有云、层级名称、业务方向名称和安全标签；不要未经用户确认就把生图结果替换进 HTML、Word 或 PDF。
