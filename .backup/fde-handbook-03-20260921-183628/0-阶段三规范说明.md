# 阶段三 · 需求确认-智能体设计——规范说明

这个阶段干什么：阶段二拿对接确认表做了原型、把需求收敛对齐了；阶段三第一件事是把收敛后的需求签字定死（需求最终确认表），再排实施计划、定业务数据口径、升级 PRD 定稿，并把一条业务链路拆成智能体矩阵——一个环节一个专用智能体，各管一段首尾相接，过 Eval 门禁才上线。一条铁律：以智能体设计为主，平台为辅。一句话主线：需求签字定稿 → 拆智能体矩阵 → 逐个照设计表填 → 配六组件 → A/B调优 → 过Eval门禁上线。

## 一、文档清单与用法

这个阶段有 5 件【交付】（1 号设计表 + 2 号需求签字表 + 3 号实施计划 + 4 号数据口径 + 5 号 PRD 定稿）和 6 份【知识】（配套方法模板）。先签字定稿需求，再照设计表逐个做智能体，用知识模板配好六组件，过测试评测。

| # | 文档 | 类型 | 怎么用 |
| --- | --- | --- | --- |
| 1 | 智能体设计表 | 📝【交付】 | 每个智能体填一份——身份卡→五层拆解→六组件→提示词→知识库→技能→A/B→验收上线，一份自包含 |
| 2 | 需求最终确认表 | 📝【交付】 | 需求收敛定稿、客户签字——项目概述/痛点/AI赋能方案/需求清单/场景/验收/四方签字 |
| 3 | 产品实施计划表 | 📝【交付】 | 需求签字后排期——前期调研/SDR部署/里程碑节点，每项带责任人·工期·前置依赖·交付物 |
| 4 | 业务数据口径模板 | 📝【交付】 | 每个指标的取数SQL+数据来源表定死，数据集优先复用 SDR 标准库；阶段④建模、阶段⑤验收对账依据 |
| 5 | 产品需求文档 PRD（定稿） | 📝【交付】 | 需求签字后升级为定稿版——目标/功能/交互三层，功能可追溯到需求 |
| 6 | 知识库配置标准模板 | 📖【知识】 | 配知识库——按类型切片灌行业知识，让智能体懂行 |
| 7 | 提示词工程标准模板 | 📖【知识】 | 写提示词——六要素结构，含招投标完整示例、版本管理 |
| 8 | 技能Skill标准模板 | 📖【知识】 | 挂技能——单一职责、输入输出规范、代码/单测/文档示例 |
| 9 | 连接器标准模板 | 📖【知识】 | 接数据——把业务数据接进智能体，含 MCP 说明 |
| 10 | AB测试标准模板 | 📖【知识】 | 调效果——对比不同方案，挑最优 |
| 11 | Eval评测标准模板 | 📖【知识】 | 过门禁——上线前质量评测，准确率达标才放行 |

## 二、标准动作流程

阶段二交棒（对接确认表 + AI能力清单 + 原型认可）：

- **① 需求签字定稿** → 填【交付】2 需求最终确认表（对接确认表收敛后的需求签字定死；同步出 3 实施计划表、4 业务数据口径、5 PRD 定稿）
- **② 拆矩阵** → 一个环节一个智能体，画出智能体矩阵
- **③ 逐个设计** → 每个智能体照【1号 设计表】填：身份卡→五层拆解→六组件
- **④ 配六组件** → 用【知识库】【提示词】【技能】【连接器】分别配
- **⑤ 测试调优** → 用【A/B测试】挑最优提示词/编排
- **⑥ 过评测门禁** → 用【Eval】，准确率达标才上线
- **▼ 交棒** → 智能体矩阵端到端能跑、准确率达标 → 阶段四做工作台

## 三、需求签字定稿（进智能体设计前先干这一步）

阶段二拿对接确认表做了原型、用原型把需求收敛对齐了；阶段三第一件事，就是把收敛后的需求签字定死，同步把实施计划、业务数据口径、PRD 定稿跟客户/研发对齐。这是后面所有智能体设计的唯一依据——需求没签、没定死，别急着设计智能体，猜错一条后面全返工。

交出这几件【交付】：

• 《2-需求最终确认表》——需求收敛定稿、客户签字

• 《3-产品实施计划表》——需求签字后排期、定交付时间（前期调研/SDR部署/里程碑）

• 《4-业务数据口径模板》——每个指标取数SQL+来源表定死，数据集优先复用 SDR 标准库

• 《5-PRD（定稿）》——需求签字后升级为定稿版，目标/功能/交互三层

## 四、智能体矩阵设计（本阶段核心方法）

四条设计原则：单一路径 / 输入输出闭环 / 边界清晰 / 可独立评测。一个环节一个智能体，上游输出=下游输入，数据流首尾闭环。手册示例链路：售前全流程（线索→策略→方案→POC→招投标）。

## 五、七条铁律

1. 需求先签字再设计智能体——需求最终确认表没签，不进智能体设计

2. 一个环节一个智能体——不越界、不重叠，数据流首尾闭环

3. 边界和异常最容易漏——正常路径谁都会写，异常兜底和转人工规则才是上线不翻车的关键

4. 提示词从五层拆解来——规则从 Playbook 提取、输入输出从节点表提取，不拍脑袋写

5. 优先用平台标准 Skill——64 个标准 skill（api-* 32 + vben-* 32）能复用就别自研

6. 准确率达标才上线——过 Eval 门禁，准确率 ≥90% 不达标不放行

## 六、做到什么算过关

• [ ] 需求最终确认表签完、需求定死，实施计划表 / 业务数据口径 / PRD 定稿同步产出

• [ ] 智能体矩阵画好——每个智能体只管一个环节，无重合无遗漏

• [ ] 数据流闭环——上游输出 = 下游输入，无断点

• [ ] 每个智能体照 1 号设计表填全，五层拆解含边界+异常

• [ ] 六组件配好——提示词/知识库/技能/连接器各按对应模板

• [ ] A/B 测试挑出最优方案

• [ ] 过 Eval 评测门禁，准确率达标

全打勾，才算智能体设计做扎实，可以交棒阶段四做工作台。
